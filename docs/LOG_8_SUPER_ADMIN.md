# Super-admin system monitoring

Dedicated platform operators sign in with their separate account, then enter /super-admin automatically. Hotel membership accounts do not gain this privilege. The UI never calls Grafana directly, and no Grafana secrets belong in VITE variables. The backend controls access and read credentials. Read-only sampled metrics, environment/role/range filters, UUID lookup, slow routes, warning/error trend and paginated events are supported. No live data or mock totals are displayed when the source is unavailable. Up to 500 exported records per query; INFO export is required for routine request telemetry. No uptime claim or complete totals. See backend docs/LOG_8_PLATFORM_MONITORING.md for setup.

LOG-8.1: dashboard count cards, P95 and warning/error trend use a separate full-window aggregate endpoint. The recent event list and slow route rankings remain limited to the most recent 500 records. Partial/unavailable metrics display unavailable, not sample counts or fabricated zeros. The existing backend read connection and filters are reused.

LOG-8.2: independent System Health panel above log filters. Manual check plus optional 60-second foreground refresh; up to 20 in-memory observations per open dashboard. API RTT includes all probes, PostgreSQL size is logical database size, and cache scope is explicit. Unreachable health endpoint does not diagnose the cause. No persistent health history or independent uptime collector yet.

LOG-8.3: Background processing panel shows scheduler and queue worker observations, push command start/completion, outbox status and optional Laravel database queue counts. Auto refresh once/minute while visible, independent of log filters. Missing/stale/unknown are not proof of downtime. Backend migration required; see backend LOG_8_3_WORKER_MONITORING.md. No retry or mutation controls.

LOG-8.3.1: 500ms filter debounce, abortable stale fetches, 30s freshness and refresh cooldown, 429 Retry-After handling with automatic resume, and recent-event Monitoring activity / Other events filters. Aggregate metrics retain all matching events. Server caching may return the previous observedAt within 30s. Legacy security warnings are correlated by request ID when the matching request appears in the same sample.
