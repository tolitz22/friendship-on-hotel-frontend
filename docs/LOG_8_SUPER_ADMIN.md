# Super-admin system monitoring

Dedicated platform operators sign in with their separate account, then enter /super-admin automatically. Hotel membership accounts do not gain this privilege. The UI never calls Grafana directly, and no Grafana secrets belong in VITE variables. The backend controls access and read credentials. Read-only sampled metrics, environment/role/range filters, UUID lookup, slow routes, warning/error trend and paginated events are supported. No live data or mock totals are displayed when the source is unavailable. Up to 500 exported records per query; INFO export is required for routine request telemetry. No uptime claim or complete totals. See backend docs/LOG_8_PLATFORM_MONITORING.md for setup.

LOG-8.1: dashboard count cards, P95 and warning/error trend use a separate full-window aggregate endpoint. The recent event list and slow route rankings remain limited to the most recent 500 records. Partial/unavailable metrics display unavailable, not sample counts or fabricated zeros. The existing backend read connection and filters are reused.

LOG-8.2: independent System Health panel above log filters. Manual check plus optional 60-second foreground refresh; up to 20 in-memory observations per open dashboard. API RTT includes all probes, PostgreSQL size is logical database size, and cache scope is explicit. Unreachable health endpoint does not diagnose the cause. No persistent health history or independent uptime collector yet.

LOG-8.3: Background processing panel shows scheduler and queue worker observations, push command start/completion, outbox status and optional Laravel database queue counts. Auto refresh once/minute while visible, independent of log filters. Missing/stale/unknown are not proof of downtime. Backend migration required; see backend LOG_8_3_WORKER_MONITORING.md. No retry or mutation controls.

LOG-8.3.1: 500ms filter debounce, abortable stale fetches, 30s freshness and refresh cooldown, 429 Retry-After handling with automatic resume, and recent-event Monitoring activity / Other events filters. Aggregate metrics retain all matching events. Server caching may return the previous observedAt within 30s. Legacy security warnings are correlated by request ID when the matching request appears in the same sample.

LOG-8.3.2: Super Admin opens on Overview (aggregate counts and trend), with System health, Background processing, and Logs & events tabs. Only the selected tab enables its query group; health and worker panels stay mounted to preserve session observations and disable interval refresh while hidden. Shared date/environment/service filters persist during tab changes. Request ID and event-type filters apply only to Logs & events; the overview remains full-window. Slow routes are still sampled and now appear below the logs. Keyboard tab navigation and responsive horizontal tab scrolling supported. No backend changes.

LOG-8.4A: separate Super Admin workspace navigation (desktop sidebar/mobile module strip) contains System monitoring and Hotels. Monitoring tabs and filters remain intact; polling stops when Hotels is selected. Hotel directory supports search and pagination, active staff/admin and room counts, and atomic creation of a Philippine hotel and first manager with forced password change. Subscription plans and enforcement are not yet implemented. No automated email, room provisioning or business date initialization. No backend credentials in browser storage.

LOG-8.4B: Subscriptions sidebar module supports a paginated PHP plan catalog, monthly/annual prices (exact centavos), explicit unlimited room/staff limits, inactive/active editing, stale revision protection and plan revision history. No prices seeded, hotel assignments, charging, trial lifecycle or enforcement. Backend migration required; no new environment variables.

LOG-8.4C: Subscriptions contains separate Hotel subscriptions and Plan catalog views. Filter/search properties, start one free trial, assign active plans, convert trial, renew at agreed terms or assign new terms after expiration. Agreement and catalog revisions protect stale edits; explicit confirmation before mutations. Asia/Manila expiry is exclusive. No automatic charge or hotel access enforcement. Backend migration required.

LOG-8.4D: subscription directory shows room and active membership usage, including 80% warnings and full/over states. Hotel staff page and room creation dialog show capacity and prevent known blocked additions; backend remains authoritative. Unassigned and unlimited resources unrestricted. Optional backend advisory mode; no new migration.
